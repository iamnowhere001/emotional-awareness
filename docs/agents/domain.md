# 领域文档布局 · mood-island

**结论：单上下文（single-context），不拆多上下文。**

## 为什么

五个子域（`content/` 数据 / `js/` 逻辑 / `scripts/` 自检 / `docs/` 文档 / `dist/` 产物）的**边界是文件类型，不是部署单元**，且交叉耦合极高——改一个内容文件必动 `index.html` + `sw.js` + `lint-content.mjs` 三个「逻辑域」文件。拆多上下文会把一次改动撕成四个 PR，而没有任何独立部署或独立语言边界作支撑。

总量也不支持拆：14 个逻辑文件约 4,400 行，自检脚本约 2,000 行，21 个内容文件约 330KB。

## 两个只读边界（本节唯一真正要传达的东西）

- **`docs/archive/`** — 历史快照，不是当前事实。永不修改，永不作为规格引用。数字过时不是漂移，是史实。
- **`dist/`** — 构建产物（已在 `.gitignore`）。永不手改；只由 `npm run build` 生成，验证靠 `npm run test:e2e:dist`。

## 文档职责边界

| 文件 | 只放什么 |
| --- | --- |
| `README.md` | 现状与数据契约（规模、题型字段、加载顺序、存档字段、红线） |
| `docs/DEVELOPMENT.md` | 怎么做（加变体 / 加站 / 加岛 / 加题型 / 自检命令） |
| `CHANGELOG.md` | 已发生的事实（含每版的「取舍」段） |
| `ROADMAP.md` | 未来与不做什么 |
| `AGENTS.md` | 代理不看就会做错的事 + 指针 |
| `GLOSSARY.md` | 开发术语单一索引（不抄数量） |
| `docs/adr/` | 不可逆决定的理由与复核条件 |
