M1 自动朗读的延迟定时器未纳入统一清理，切屏后仍会朗读

问题
开启“进站自动读题”后，renderLevel 注册一个 setTimeout(…, 350) 直接调用 speakTexts(questionTexts())。该定时器既没有保存句柄，也不在 clearAsyncTimers() 的清理清单里（清单只清 breathTimer / memoTimer / restTimer）。
影响
进站 350ms 内点“返回地图 / 换档 / 进急救”等切走视图时，stopSpeech() 先取消了朗读，但延迟回调随后触发，从新页面抓取文本继续朗读——离开关卡后仍蹦出声音，且读的是不相干内容。对一个用于安抚情绪的应用，这是明显的体验破坏。
相关文件
js/views-level.js:315-317 · js/shell.js:279-286（clearAsyncTimers）· js/shell.js:287-301（stopSpeech / speakTexts）
建议
把该 timer 句柄存进一个模块级变量（如 speakTimer），加入 clearAsyncTimers() 一并 clearTimeout；同时在回调内再校验 session.view === 'level' 且关卡 id 未变，双保险。

M2 缺少全局错误兜底，运行期异常会静默白屏

问题
全项目没有 window.onerror / unhandledrejection 监听，也没有全局 error 事件处理。现有的兜底只在启动期（CONTENT_OK）与 hashchange 的 try/catch，覆盖不到渲染过程中的异常。
影响
任何未预期的异常——内容字段缺失导致某个 RENDERERS[type] 抛错、speechSynthesis 在个别设备抛错、导入数据边界外的畸形值——都会让 stage.innerHTML 停在半途：用户看到空白或残缺页面，没有任何提示，也不知道怎么恢复。键盘与读屏用户尤其无助。
相关文件
index.html:16-48（#stage 容器）· js/boot.js:107-149（仅启动兜底）· js/core.js:121-122（CONTENT_OK）
建议
在 boot.js 顶层注册 window.addEventListener('error', …) 与 'unhandledrejection'，统一渲染一张可读错误卡，提供“返回地图 / 重新载入”出口；保留 console.error 便于排查。注意不要把已知无害的静默失败（如语音不支持）误报给用户，可在处理器内白名单过滤。

M3 多标签页会静默互相覆盖进度（数据丢失）

问题
save() 每次都把内存里的整份 state 全量写入同一个 localStorage 键；项目没有任何 storage 事件监听。
影响
同一应用开两个标签页：A 页玩出新进度并保存；B 页仍持有旧 state，此时 B 页任何一次写操作（通关、换档、调字号、导入）都会用旧快照整体覆盖，A 的进度无声消失。多标签浏览是常见习惯，这是真实可达的数据丢失路径。
相关文件
js/core.js:236-257（load / readRaw）· js/core.js:368-376（save）· js/boot.js（无 storage 监听）
建议
在 boot.js 监听 window 'storage'，检测到 STORAGE_KEY 被外部修改且本地有未保存变更时，弹出提示让用户选择“用最新进度继续（重载）”或“保留当前”；最低成本方案是检测到外部写入即提示刷新，避免无声覆盖。
建议优化

不阻塞发版，但影响性能、健壮性或长期可维护性，建议排入近期迭代。

S1 运行时游标 levelIndex 混入存档，但不进迁移白名单

问题
state.levelIndex 是“当前正在看哪一关”的运行时游标，被直接挂在持久化对象 state 上，随 save() 写进 localStorage 与导出 JSON；但它既不在 DEFAULT_STATE，也完全不被 migrate() 读取。
影响
同一个对象一半是持久数据、一半是临时状态，语义混淆。导出文件会带一个未在契约中声明的字段，导入后该字段丢失、行为与导出前不一致。当前不致丢进度（重进会重算），但属于数据卫生欠账，未来一旦有人依赖它恢复位置就会踩坑。
相关文件
js/core.js:183-210（DEFAULT_STATE / state）· js/core.js:315-352（migrate）· js/actions.js:25,34,42 · js/shell.js:184 · js/boot.js:83
建议
把 levelIndex 移到 session（如 session.levelIndex），彻底不落盘；或反过来在 DEFAULT_STATE 与 migrate() 中显式声明它——二选一，别维持当前“默默写入又默默丢弃”的中间态。

S2 首屏 26 个脚本阻塞加载 + 全量内容数据（100KB CSS / 88KB 词典）

问题
index.html 用 26 个普通 <script src> 顺序加载，无 defer；style.css 100KB、content/dictionary.js 88KB、题库多份大文件全部随首屏解析。
影响
file:// 双击与 PWA 二次访问（SW 预缓存命中）影响很小；但 http(s) 冷启动、弱网或低端设备上，26 个串行请求 + 全量数据解析会明显拖慢首屏。词典/自助/慢变量在首屏根本用不到。
相关文件
index.html:51-77 · style.css（100K）· content/dictionary.js（88K）· sw.js:23-56（预缓存清单）
建议
优先做零风险的一项：给纯逻辑脚本加 defer（defer 保序，不破坏“顺序敏感”契约），让 HTML 解析与脚本下载并行。更大收益需按视图动态加载重型内容，但会触碰“零构建 / file:// 可用”红线——务必在守住这两条的前提下评估，因此列为建议而非必须。

S3 数字键快捷键只取第一组，部分声明支持的元素实际按不到

问题
键盘处理里 [opts, rungs, others].find(g => g.length)?.[n] 只命中第一个非空组。others 组把 .pair-item / .word-chip / .weather-btn / .chip / .clue-card 混在一起。
影响
线索关同时存在 .opt（clue-choose 选项）与 .clue-card（可翻的线索卡）。此时第一组恒为 .opt，数字键永远只点选项，.clue-card 虽被列入“支持数字键”却无法用数字键触发。代码注释声称这些题型都支持数字键，实现与声明不一致。
相关文件
js/boot.js:56-67 · js/views-level.js:52-58（clue 渲染，opt + clue-card 共存）· js/util.js:123-129（optBtn 的 aria-keyshortcuts）
建议
按题型明确数字键映射：或合并所有可见选项为单一有序列表；或在 VIEW_CONFIG / 题型配置里声明当前关的数字键目标选择器，避免用一个 find 猜组。同时保证 aria-keyshortcuts 与实际可触发元素一致。

S4 多段语音朗读存在中途静默（speechSynthesis 已知问题）

问题
speakTexts() 对文本数组 forEach 逐条 speechSynthesis.speak(u)。Chrome 对一次性排入多段 utterance 有已知缺陷：约 15 秒后可能静默停住（“读选项”尤其容易触发）。
影响
依赖朗读的用户（视障、阅读困难、低龄儿童）点“读选项”时可能听一半就断，且没有可见提示说明为何停止。文字仍在页面上，属体验降级而非功能丧失。
相关文件
js/shell.js:288-301（speakTexts）· js/actions.js:452-453（speak-question / speak-options）· js/actions.js:173-183（另一处 speak 调用）
建议
把多段文本合并成一条 utterance（用标点连接）一次播完；或在前一段的 onend 里调度下一段，并用周期性 resume() 保活。stopSpeech() 的取消逻辑需相应调整。

S5 Service Worker 安装 / 注册失败被双层静默吞掉

问题
SW 的 install 链尾 .catch(() => self.skipWaiting()) 让预缓存失败时仍激活；boot.js 的 register().catch(() => {}) 又吞掉注册失败。代码注释已明确承认“两层各自静默叠加”。
影响
预缓存清单中任一资源 404 会导致离线能力不完整，但用户与开发者都看不到任何信号，仍以为装好后可离线用。玩法本身不受影响（离线能力不是前提），故列为建议。
相关文件
sw.js:7-20（注释自述）· sw.js:58-75（install / activate）· js/boot.js:92-105（registerOffline）
建议
至少在预缓存失败的 catch 里 console.warn 并标记缓存不完整；设置页可暴露“离线可用 / 不可用”状态，让 PWA 门槛（路线图条件 2）可被真实验收。

S6 缺少 Content-Security-Policy（纵深防御）

问题
index.html 没有 CSP。当前应用没有用户输入拼接进 HTML、无外部资源、无 eval，实际 XSS 风险很低。
影响
属纵深防御缺口而非可利用漏洞：一旦将来引入第三方脚本或新的注入点，没有第二道防线。定级为建议优化，避免误导为“安全问题”。
相关文件
index.html:1-15 · js/util.js:7（esc）· js/views-library.js:186（搜索词走 textContent）
建议
加 <meta http-equiv="Content-Security-Policy" content="default-src 'self'; style-src 'self' 'unsafe-inline'; …">。注意 file:// 下 CSP 行为特殊，需实测不要把 noscript 内联样式与必要的内联样式挡掉；若要杜绝内联样式，成本较高，可按项目实际决定。
可选增强

打磨性质，或与发布流程相关而非代码缺陷，视资源决定是否处理。

O1 manifest 固定竖屏，平板横屏体验受限

问题
manifest.webmanifest 设置 "orientation": "portrait"，装到主屏后强制竖屏。
影响
在平板、折叠屏或横屏支架上，词典宽表格与地图被迫挤在竖屏宽度里，空间浪费。
相关文件
manifest.webmanifest（orientation 字段）
建议
改为 "any" 或 "natural"，让系统与应用自行决定方向；项目已有 320px–1280px 响应式样式，横屏能自然适配。

O2 未适配 Windows forced-colors 高对比模式

问题
style.css 有手动 .high-contrast、prefers-color-scheme、prefers-reduced-motion，但没有 @media (forced-colors: active)。
影响
Windows 高对比模式下系统会覆盖自定义配色，地图岛屿、进度圆点等靠背景色/边框区分的图形可能失去层次。已有手动高对比模式兜底一部分，影响有限。
相关文件
style.css:1295-1315（high-contrast 规则）· style.css:1601（prefers-reduced-motion）
建议
对关键图形元素补 @media (forced-colors: active) 规则，使用系统色关键词（CanvasText / Canvas / Highlight）并确保用边框而非仅背景色传达状态。

O4 没有“添加到主屏”引导（PWA 门槛条件 2）

问题
SW 与 manifest 配置齐全，但应用没有捕获 beforeinstallprompt，也没有任何引导用户安装的入口。
影响
路线图把“PWA 主屏实际安装实测”列为未满足门槛；缺少引导会让安装率很低，也让该门槛更难完成。
相关文件
js/boot.js:92-105（仅注册 SW）· js/ui.js:223-278（设置弹窗，可承载入口）· manifest.webmanifest
建议
捕获 beforeinstallprompt 暂存事件，在设置弹窗加一个“安装到主屏”按钮，用户点击时调用 prompt()；同时保留手动引导文案以兼容 iOS Safari。
值得保留

这些不是“没问题”，而是主动做对了的工程实践，重构时请勿破坏。

  • 存档迁移白名单 + 损坏 JSON 多键回退，旧档不丢、脏数据不进内存
  • localStorage 不可写时显式提示用户，不假装保存成功
  • 通关用 awarded 去重，贝壳/词卡不重复发放；支线进度与主线物理隔离
  • 全部用户输入经 esc 或 textContent，无 eval / document.write / 外部链接
  • 路由对非法 hash、坏 percent-encoding 就地降级，不白屏
  • 视图切换统一清定时器与语音；呼吸计时器被中断有状态标记
  • 导入做来源 / 结构 / 版本 / 大小校验，确认前不改状态，且可撤销一次
  • focus-visible、aria-live、reduced-motion、深色模式、44px 触控目标齐备
  • 版本六处一致、脚本清单与 SW 预缓存覆盖、README 加载顺序均有自动自检
  • 三轮质量脚本 check / lint / doctor 本次实跑全部通过
