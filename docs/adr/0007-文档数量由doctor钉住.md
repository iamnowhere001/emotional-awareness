# ADR-0007 文档里的数量由 doctor 钉到实测值

- 状态：Accepted（2026-11-26）
- 日期：2026-11-26

## 上下文

同一个数字（站数、变体数、概念数、版本号）在 `README.md` / `ROADMAP.md` / 源码头注释 / `index.html` 的 meta 里各写一份，无法靠人记同步。`npm run doctor` 用正则把「一段具体措辞 + 一个数字」匹配到运行时实测值。

## 决定

不靠人记，靠正则钉：每个写死的数量必须落在一条 doctor 断言里，断言同时检查「值对不对」与「措辞没变」。本仓库零构建，没有代码生成这条路可选。**断言默认 fail-closed**：一处也匹配不上即 FAIL，除非该项登记进 `DOCNUM_OPTIONAL` / `SCALE_EXEMPT` 并写明理由。

## 后果

放弃的：措辞自由。「N 关 + 终章」不能改成别的写法而不同批改正则；术语统一必须与 doctor 正则同批提交。
换到的：断言让数字不可能在任何一次提交后过时，且不需要人记住它们在哪。

**已修掉的历史缺陷**：`docNum()` 原本是 fail-open（零命中即 PASS），于是「删内容 / 拆文件 / 改措辞」三种看似无害的操作都会让断言静默消失，而 PASS 总数不变。这就是当初「文档已经漂了 5 处、doctor 仍然全绿」的原因。

**仍存的已知局限**：命中数从 2 变 1 也仍 PASS（约束从双份悄悄变单份）。要挡得给每项配 `expectedHits`，但那会把「有意精简文档」判红，与精简方向冲突，故**明确不做**。防护方式是改完逐行看 doctor 的细节文本，而不是看 PASS 总数。

## 复核条件

若同一项数字的副本数降到 1（不再需要在多处同步），这条 ADR 的前提消失，可整体撤掉这批断言。
