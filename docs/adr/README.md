# 架构决定记录（ADR）

只记录**同时满足三条**的决定：不可逆 + 会影响未来无数个小决定 + **后来者看到会想「优化掉」它**。

不记录：可测量的现状（→ `README.md`）｜一次性的版本决定（→ `CHANGELOG.md`）｜计划与优先级（→ `ROADMAP.md`）｜`git log` 能查到的事实。

## 编号与状态

- 文件名 `NNNN-dash-case.md`，四位递增。
- **只增不改**。决定被推翻时新写一条，旧的在头部加 `状态：Superseded by ADR-00XX`，正文保留。
- 状态取值：`Accepted` / `Superseded by ADR-XXXX` / `Superseded` / `Deprecated`。

## 模板（不超过 15 行）

```markdown
# ADR-XXXX 标题

- 状态：Accepted（YYYY-MM-DD）
- 日期：YYYY-MM-DD

## 上下文
两句话：当时的约束是什么。

## 决定
一句话。

## 后果
放弃了什么，诚实写。

## 复核条件
具体到什么情况下重开——**这一段是 ADR 的全部价值所在**。
```

不写备选方案的长篇对比——那是评审文档，不是 ADR。
