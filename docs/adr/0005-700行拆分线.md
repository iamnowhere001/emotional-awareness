# ADR-0005 700 行拆分线只做纯搬运

- 状态：Accepted（2026-11-26）
- 日期：2026-11-26

## 上下文

早期 `script.js` 单体涨到不可维护，0.12.0 起按 700 行触发线拆分。混在搬迁里的行为改动会让「出问题是哪次改动造成的」无法二分。

## 决定

单文件超 700 行即排期拆分，且**拆分只做搬运，行为一字不改**；行为改动单独提交。拆分必须同批同步 `scripts/js-files.mjs` / `index.html` / `sw.js` 三处清单。

## 后果

放弃的：拆分时顺手「理一理」的机会成本（要理另开一笔）。
换到的：拆分提交可以用「零行为变更」独立验证；出问题时 `git revert` 那一笔就够。

**已知局限：700 行不是「深模块」判据。** 实测反例——`js/views-dictionary.js` 404 行却是全库唯一深模块（接口极窄、实现极厚），`js/actions-level.js` 483 行才是真问题（交互表散落、防线靠调用方兜底）。裁决模块深浅请看接口宽度与调用方是否被迫了解内部，不要只看行数。

## 复核条件

若出现「单文件远低于 700 行但改一处要同时改 5 个文件」的普遍现象，说明判据该换成「跨文件耦合度」，届时重开。
