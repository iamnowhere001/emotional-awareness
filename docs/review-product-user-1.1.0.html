心情闯关岛 · 产品与用户双视角审查

审查对象：本地工作区 v1.1.0（tag v1.1.0 / commit a089b88）　·　日期：2026-11-20　·　方法：三条独立只读审查线（产品文档 / 代码体验 / 内容质量）交叉验证

一个在「不做什么」上极其清醒、在「有没有用」上几乎空白的高完成度作品。

工程与安全水位明显高于内容真实感水位；代码把用户当人看，内容有时把用户当「题目受众」。最大的产品风险不是功能缺口，而是验证通道被主动关闭。

下文的评分是基于证据的主观判断，不是客观测量——欢迎逐条反驳。凡「有意不做」的设计取舍单独列出，不按缺陷计。

修复状态（2026-11-20）：「如果只做三件事」的第 1、2 项已执行——8 处数字漂移已修并新增 23 条 doctor 护栏、3 处儿童职场情境已改、词典危机词条已接通站内急救出口，verify 全绿（doctor 45 PASS / 242 PASS）。第 3 项（真实用户观察）需谢衣安排真人，未执行。另：复核发现初稿把 bank-compose.js:60 误列为儿童档，实为成年档反例，已从清单移除（见 §4.2 更正说明）。改动未提交。

一、核心判断

01

这是「作品」多于「产品」

六条红线、明确的取舍表、近乎洁癖的文档与回归纪律，都指向一个高度自洽的表达系统。但全库找不到用户研究、留存数据或竞品分析，且在 CHANGELOG 里明确放弃效果评估。价值主张从未被外部证伪，也从未被证实。

02

工程安全 ≫ 内容真实感

代码层做得扎实：不打分、温柔重试、危机分流、无障碍全覆盖、隐私不可写兜底、白屏可读提示。内容层却把 6–12 岁孩子放进「接项目」「连着开会」的职场情境，成年档议题窄到几乎只剩工作压力。

03

取舍可以，代价要被看见

「不打卡、不追踪、不做问卷」与红线自洽，不是疏漏。但「不制造压力」与「验证有效性」并非不可调和——当前选择是整体放弃验证。产品的天花板由此决定，而不是由内容量决定。

2.1 定位与价值主张 强

「一起认出心里的天气」在 README.md:3、manifest.webmanifest:2、README.md:7 三处一致；六条红线（不打分、不采集、不联网、不宣称疗效、不打卡、不制造压力）贯穿文档。产品任务被定义为「把模糊的感觉看得更清楚一点，再带走一个用得上的小工具」，并明确否认「心理测评 / 诊断 / 治疗替代」（README.md:226）。这是同类科普产品里少有的边界清晰度。

2.3 留存：只有内容供给，没有成长回路

「不打卡 / 不连续登录 / 进度不会掉」写在 README.md:227 红线 5，ROADMAP.md:72 直接把打卡方案判为与红线冲突。现存回访动力只有：漂流瓶可换一题、每关多组变体、seen 暗记录（每关最多 8 条，界面不显示，README.md:173）。成长记录是通关式（cleared / cards / skills），刻意不记次数、天数、时长。

判断

「不制造回来的压力」是对的，但「不制造压力」≠「不给任何反馈」。当前设计里，孩子通关后看不到「我收集到了什么」的即时回响（详见 3.4），这是可以在不违反红线的前提下补的回路。

2.4 竞品与差异化：完全没有论证

文档未提及任何对标产品、市场规模、获客渠道。「为什么选它而不是别的情绪 App」的唯一答案是六条红线本身。而 ROADMAP.md:73 把金句 PNG、打印词卡、多语言判为「传播价值不等于产品价值」放进候选池不排期——这个判断可能正确，但它同时切断了低成本传播路径，且没有数据支撑。

2.5 数据伦理：最强的护城河

不保存天气选择、心情文本、主题筛选；localStorage 只存进度类字段（README.md:164-167）；导出导入做六层校验、覆盖前预览、一次撤销（README.md:185-198）；危机口径经人工复核，12356 不承诺全国 7×24、儿童档只引导找大人不含号码（docs/crisis-review-1.0.0.md）。这一块的水位显著高于同类产品。

3.1 首次上手：顺，但低龄孩子进不来 可修

路径是「选档 → 首页 → 开始上岛 → 第一关天气题」，共两次点击（boot.js:225-231 → views-main.js:12-29 → actions-data.js:5-22 → actions-level.js:7-15）。没有任何交互式引导或示例，只有文字说明。选档页全文字、无语音无图标（views-main.js:16-26），3–6 岁不识字的孩子无法独立进入；进 a3 档后是 emoji 点选与大按钮，但朗读要手动点喇叭，而进站自动读默认关（core.js:189 的 autoSpeak:false）。

证据：views-main.js:18-25 选档 lead 为纯文字；bands.js:11 a3 字号 1.18、语音默认 true，但 core.js:189 autoSpeak 默认 false；views-level.js:279-280 需手动「读题目」。

3.2 不打分：守得最牢的红线 强

点错只走 nudge()（shell.js:232-244）：「也是一种可能」「再看看」加轻微抖动，第二次才给提示；全库无红叉、无「错误 / 扣分 / 不及格」。内部确有答案比对，但只决定「完成」还是「温柔重试」；连拼句题选了不温和的句子也允许「就用这句，继续」（actions-level.js:373-381）。这一条做得很实，不是文档说说。

3.3 情感安全与危机分流 强

顶栏常驻「现在很难受」并 sticky 吸顶（index.html:43、style.css:64-67），首页、地图、所有弹窗都有「先缓一缓」出口。儿童 / 成年口径分流明确（core.js:177-180）：孩子看到「先去找身边的大人，不要一个人待着」，大人看到 12356 / 120 / 110 / 急诊（views-main.js:126-129,155-165）。未发现疗效承诺或「必须原谅 / 想开就好」类二次伤害。

四、内容视角（用户价值的实际载体）

4.1 覆盖与深度

五岛覆盖喜怒哀惧、羞耻、内疚、嫉妒、孤独，心理学内容的水位高得意外：162 条词典主动标注争议与 myth（情绪建构论「仍是正在争论的理论」dictionary.js:32、正念「效应量小到中等」:73-74、马斯洛「跨文化研究不支持严格顺序」:163-165），措辞保守。但缺自豪 / 希望 / 感恩 / 敬畏这类正向情绪主题；成年档的亲密关系仅 1 处、存在意义与哀伤在关卡层近乎空白。

4.2 适龄性硬伤 P0

儿童题库混入成人职场情境，直接打断 6–12 岁孩子的代入感：

bank-kid-island4.js:130「老师问你能不能再接一个项目，你手上已经很满了」（a6）
bank-kid-1-3.js:877「连着开了几个会，不想再说话」
bank-kid-island4.js:71「在群里下不来台」

这是 1.1.0 儿童文案降级那一轮漏掉的——当时聚焦临终意象与超龄术语，没有全量扫「成人职场语境」。同轮还留下 bank-kid-island5.js:95「觉得没人需要你」这类对孩子偏重的表述。

复核更正：初稿把 bank-compose.js:60「我这辈子都不会原谅自己」误列为儿童档，实际它属于 A4-3（b:['adult']，bank-compose.js:91）。成年档里这是「要被否定的坏想法」反例，按设计保留，不属适龄性问题。

4.3 成年档深度名不副实 P1

岛 4/5 与儿童档几乎同构（levels-adult.js:88-111 vs levels-kid-island4.js:7-34），职场场景高度重复（方案被否、同事推活、周末加班）。真正成人化的部分存在但零散：反刍 / 倦怠 / 内耗、读心术 / 去灾难化 / 应该句式、维持行为（bank-adult-1-3.js:143-151,229-264,277）。工作间支线（4 幕：会前紧张 → 汇报被否 → 冲突表达 → 下班反刍，levels-adult-work.js:7-127）是成年档最有价值的设计，但藏在 A3-4 解锁门槛后、不计入主线、不给任何反馈。

4.4 变体与一致性

变体质量参差：有的确是不同情境（积木倒了 vs 妈妈拿出饼干），有的只是换词（天气四组都只是「选天气」）。tier 2 常是 tier 1 同场景加一张卡（bank-kid-1-3.js:596 与 :644 同为「群里发话没人接」）。个别语句问题：bank-kid-island4.js:95 同义重复、:81-84 指代错位。另有 bank-compose.js:102-111,124-133 与 bank-adult-island4.js:42-55 完全重复，而 util.js:97 优先取 compose，后者是不可见的死数据。

P0文档数字漂移 6 处，其中 1.1.0 刚引入 3 处

同一份 README 里「每轨 4 座岛」与「21 站（5 岛）」并存，「91+32=123 组」与正文「111+41 组」并存，「儿童超龄术语待改写 / 未改」与实际已改并存。源码注释也停在旧值。

README.md:30 每轨 4 座岛　README.md:33 91+32=123　README.md:282 标注「未改」　glossary.js:1 16 个概念（实为 20）　levels-kid.js:1 16 站（实为 21）　levels-adult-work.js:3 17 站　DEVELOPMENT.md:111 固定 16 个概念

根因：doctor 只校验「当前版本章节 + ROADMAP 全文」的规模数字，正文描述与源码注释不在覆盖内。这是我在 1.1.0 收尾时改了正文表格、漏了其他地方。

P0儿童题库的成人职场情境

适龄性硬伤，影响 6–12 岁核心用户。纯文案替换，不改结构、不动题库字段，风险低。

bank-kid-island4.js:130 / bank-kid-1-3.js:877 / bank-kid-island4.js:71（初稿第 4 处经复核属成年档反例，已从清单移除）
P1词典自杀风险词条不指向站内急救入口

这是 0.13.0 审核时就记录的已知安全链路断点（docs/archive/content-review-0.13.0.md:82）：用户在词典里读到风险词条时，旁边没有一个直达「现在很难受」的出口。与产品的安全定位相比，这个断点的优先级应该高于任何新内容。

P1验证脚本的覆盖盲区

回归脚本 79 项源码断言 + 163 项浏览器用例守住了结构与行为，但守不住「文档自述 vs 实际」的一致性——6 处漂移全在验证网之外。这是 P0-1 反复发生的机制性原因，改数字不改网，下次还会漂。

P2低龄入口 / 成年档深度 / 变体冗余

三项都是「不致命但拉低价值感」：a3 选档与朗读默认（views-main.js:18-25、core.js:189）；成年档议题过窄（关卡层无亲密关系 / 哀伤 / 存在意义）；4-3 与 A4-3 双题库冗余使其中一份成死数据（bank-compose.js:102-133 vs bank-adult-island4.js:42-55）。

六、设计取舍（不建议改，但代价要认）

取舍为什么合理需要承认的代价
不打卡 / 不连续登录 / 进度不掉与「不制造压力」红线一致，且避免把情绪练习变成任务没有成长回路，通关后缺少回来的理由
不记录心情文本 / 不做问卷与前后测隐私优先，且避免把表达变成数据产品是否有效永远不可知，无法迭代价值主张
无账号 / 无云同步 / 无多语言纯前端离线形态，换设备用导出 JSON跨设备体验断裂；成年旧进度明确不映射（README:183）
选档需要大人参与「亲子」定位下，3–6 岁由大人陪着选是合理的但 3–6 岁档对外表述应诚实标注「需陪玩」，否则是能力错配
金句 PNG / 打印词卡 / 多语言放候选池传播价值不等于产品价值，成本不低切断了低成本自传播路径

七、如果只做三件事

  1. 修掉 6 处数字漂移，并把「文档自述 vs 实际」纳入 doctor 校验。 纯文案，零行为风险；同时堵住漂移复发的机制。这是当前唯一「确定是 bug」的部分，而且是我上一轮留下的。
  2. 清掉儿童题库的成人职场情境（3 处，复核后），顺手把词典风险词条接上急救入口。 前者修适龄性，后者补安全链路，两项都是字符串级改动，收益直接落在核心用户身上。
  3. 做一次最小验证，而不是补内容。 不必上问卷或前后测——可以是 3–5 位真实家长 / 成年用户的出声思考观察，只看两件事：孩子能不能自己走到第一关、大人能不能说清「这东西对我有什么用」。这是目前唯一能改变产品判断的动作，其余优化都只是在既有假设上打磨。

一句话收尾

这个应用的边界感、工程质量和安全水位，已经超过绝大多数同类作品；它现在缺的不是更多的岛和词卡，而是一次「把它交到真实用户手里、看会发生什么」的勇气。第 3 件事比前两件都难，但也只有它决定这是不是一个产品。

审查方法：三条独立只读线（产品文档 / 代码体验 / 内容质量）并行取证，交叉验证后按「真问题 / 设计取舍」分类。所有引用均指向 v1.1.0 工作副本的文件与行号。本报告未修改任何应用代码或内容文件。
